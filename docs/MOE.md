# 稀疏混合专家（Sparse MoE）

## 结构

每个 token 经过 Top-K 路由，只激活 K 个专家。Kolibri-1 是 78.1B 总参数、
每 token 约 3.46B 活跃（稀疏比 ~22.6×）。

## 两个必踩的坑

### 1. 路由塌缩

若不加约束，路由会塌缩到少数几个专家——省算力的目的就废了，还热点拥塞。
解法：**负载均衡辅助损失**（见 `moe/balance.py`，用负载分数的变异系数平方）。

### 2. 门控权重归一化

Top-K 选中的专家，其门控权重要在 K 个专家内重新归一化（softmax 后截断再归一），
否则梯度分布不对。

## 专家结构

每个专家是 SwiGLU FFN：`W2 @ (swish(W1@x) * (W3@x))`。
